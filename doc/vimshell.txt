1. INTRODUCTION                                         *vimshell-introduction*

VimShell is Emacs shell-mode in Vim: a buffer with ONE persistent shell
underneath (a job over pipes, no pty). The shell writes straight into
the buffer; Vim captures no streams. Prompt lines are editable like any
Vim text, everything else is read-only. What you send is exactly what
you typed.

Typing "exit" kills the shell; pressing <CR> restarts it.

Requires Vim with |job| and |channel| support (":echo has('job')" is 1).

==============================================================================
2. USAGE                                                       *vimshell-usage*

To start VimShell, use any of the following commands:

    :VimShell          Open in current window
    :VimShellOpen      Open in a new window
    :VimShellSplit     Open in a horizontal split
    :VimShellVSplit    Open in a vertical split

Type on a prompt line, <CR> sends it. <CR> on an old line copies it to
a fresh prompt instead of executing (like Emacs). <CR> on empty input
sends a newline. The prompt is printed by the shell itself, so it
always follows the output.

Completion is Tab-driven: commands on the first word ($PATH plus common
builtins), paths on the rest (relative, absolute and ~/..., directories
with trailing /), flags of the command when the fragment starts with -
(from --help, cached per command). One candidate replaces the fragment;
several extend the common prefix or get listed right in the buffer,
without touching what you typed. Anything else is Vim's native
completion on editable text (i_CTRL-X_CTRL-F for files, i_CTRL-N for
words...).

The buffer has shell highlighting (prompt, strings, $variables,
comments, numbers, operators, flags, suspicious errors).

==============================================================================
3. COMMANDS                                                 *vimshell-commands*

:VimShell          Open VimShell in the current window.
:VimShellOpen      Open VimShell in a new window.
:VimShellSplit     Open VimShell in a horizontal split.
:VimShellVSplit    Open VimShell in a vertical split.
:VimShellShell {shell}
                 Use another shell for new buffers.

==============================================================================
4. MAPPINGS                                                 *vimshell-mappings*

<CR>             Send the current prompt line (RET).
<CR> on old line  Copy it to a fresh prompt (like Emacs).
<CR> on empty     Send a newline.
<C-p>/<Up>       Previous history entry (M-p).
<C-n>/<Down>     Next history entry (M-n).
<Tab>            Complete: commands, paths or flags (-x, --long).
<C-c>            Real SIGINT to the job.
<C-d>            EOF with empty input (closes the shell).
<C-l>            Clear the buffer.

5. CONFIGURATION                                       *vimshell-configuration*

g:vimshell_shell          Default: $SHELL (or 'sh')
    The shell to run. It is invoked with -i so it loads your rc file
    (aliases, prompt...). bash is also passed --noediting because it
    uses readline even on pipes. fish cannot work (see below) and
    falls back to sh with a warning.
    Example: >
        let g:vimshell_shell = 'bash'

g:vimshell_prompt         Default: 'vimsh$ '
    Prompt template, expanded once when the shell starts: $PWD (Vim
    cwd at that moment), $HOME, $USER, $SHELL, $HOSTNAME and their
    ${...} forms; $$ is a literal $. Anything else is removed so the
    prompt stays static and recognizable. Single-line only.

==============================================================================
6. LIMITATIONS                                           *vimshell-limitations*

No pty means no magic:

- No interactive programs: vim, less, htop, fzf... need a terminal,
  use |:terminal| for those. "clear" works (handled by the buffer).
- fish is unusable as the inferior shell: with piped stdin it reads
  to EOF before executing anything.
- The prompt is static per session; plain "cd <dir>" still moves Vim
  too (keeps completion honest) but the printed prompt won't follow.
- If your rc prints a prompt unconditionally you will see extra
  lines: guard it with "[ -t 1 ] && PS1=...".
